# 마른길 문서 정합성 평가서

> 평가 버전: rev.2  
> 평가일: 2026-08-11  
> 대상: 기술리드 배포판 rev.5, MVP Specification rev.1, 온라인 해커톤 1일차 회의 자료, 기존 MVP 설계서·요구사항 정의서, 현재 체크아웃의 계약·데이터 산출물

## 1. 평가 결론

기존 문서에는 실행 시 충돌을 일으킬 수 있는 용어·수치·범위 차이가 있었다. 아래 결정을 반영해 [MVP 설계서 rev.3](./마른길_MVP_설계서.md)와 [요구사항 정의서 rev.3](./마른길_요구사항_정의서.md)를 같은 기준으로 갱신했다.

현재 남은 것은 문서 간 해석 충돌이 아니라 G0~G2에서 만들어야 할 계약·픽스처·수동 데이터와 현재 체크아웃에 없는 구현물이다. 이 항목은 완료된 것으로 표현하지 않고 공개 미결정 또는 구현 미확인으로 표시했다.

## 2. 기준 자료와 우선순위

| 우선 | 근거 | 적용 범위 |
|---:|---|---|
| 1 | 현재 데이터 산출물·계약 스키마 | enum, 필드, 모델 수치, 실제 픽스처 센서 수 |
| 2 | MVP Specification rev.1 | 제품 범위, 화면, 정책, 계약 의미 |
| 3 | 기술리드 배포판 rev.5 | 모듈 책임, 경로 구현 보고, 게이트와 작업 순서 |
| 4 | 해커톤 1일차 회의 자료 | 설명, 담당자 업무, 준비일 진행 방식 |

우선순위가 낮다는 것은 자료를 폐기한다는 뜻이 아니다. 상위 근거와 모순될 때 수치·enum·범위를 덮어쓰지 않는다는 뜻이다.

## 4. 공통 용어 사전

| 사용 용어 | 정의 | 쓰지 않을 표현 |
|---|---|---|
| 과거 하수 수위 원본 | 2022년 명목상 1분 간격이며 누락이 있는 기록 | 현재 1분 실시간 관측 |
| 고수위 확률 | 센서별 horizon 내 고수위 가능성 | 도로 침수 확률 |
| AI 예측 위험 | 팀 합의 임계값으로 `risk_probability`를 구분한 `LOW/HIGH` | 최종 서비스 위험 `SAFE~SEVERE` |
| 추천 후보 경로 | 공식 대피경로 중 상대적으로 위험이 낮은 후보 | 안전 경로, 최적 경로 |
| 정보 없음 | 범위 밖 또는 필수 데이터 단절로 판단 불가 | UNKNOWN |
| 경로 데이터 판단 불가 | 데이터 누락·미연결로 경로 존재 여부를 판단할 수 없는 `DATA_UNAVAILABLE` | 경로 `UNAVAILABLE` |

| 공식 정보 | 경보·대피·도로/하천 통제 등 공적 근거 | AI 예측과 혼합된 단일 점수 |
| 팀 규칙 | 해커톤에서 합의한 보수적 임계 | 공식 안전 기준 |
| MVP 프로필 | 고령자·아이 동반만 지원 | 휠체어·반려동물 동반 지원 |

## 5. 현재 체크아웃과 목표 설계의 차이

평가 시점에 `services/predictor/`, `services/decision/`, `services/route/`, `web/`, `policy/`, `api/` 디렉터리는 현재 체크아웃에서 확인되지 않았다. 반면 모델 관련 데이터·스크립트·위험 픽스처와 다음 두 계약은 확인됐다.

- `contracts/schema/risk_assessment.schema.json`
- `contracts/schema/action_decision.schema.json`

따라서 다음 항목을 통합 전에 반드시 확인한다.

| 체크 | 완료 기준 | 게이트 |
|---|---|---|
| 구현 브랜치·배포본 위치 | rev.5에서 보고한 predictor/route 코드가 통합 대상 브랜치에 존재 | G0 |
| `SafeRoute` 스키마 | 필수 상태와 제한 필드가 예제와 함께 검증됨 | G0 |
| `AssessResponse` 스키마 | `clock`과 3개 도메인 결과가 UI 예제로 렌더링됨 | G0 |
| 공식정보 픽스처 | 출처·발효시각·해제시각·통제 유형 포함 | G0 |
| 경로 범위 정합 | 범위 내 센서 수와 지역 위험 계산법 기록 | G1 |
| 정책·프로필 동결 | 임계값과 P1/P2 초안이 테스트와 함께 확정 | G2 |

## 7. 팀 공유 체크리스트

- [ ] 모든 역할이 행동 enum 5개와 위험 enum 4개를 그대로 사용한다.
- [ ] “1분” 앞에는 과거 원본·명목상 간격·누락 설명을 붙인다.
- [ ] 현재 경로를 안전·최적·검증 완료로 부르지 않는다.
- [ ] 모델 성능 발표에서 85.3%와 Logistic 87.7%를 혼동하지 않는다.
- [ ] 모델 픽스처는 `RF-*`, 통합 데모는 `DS-*`로 부른다.
- [ ] MVP 프로필은 고령자·아이 동반만 제공하고 휠체어·반려동물 동반 선택지는 노출하지 않는다.
- [ ] 데모 시각은 공식 픽스처 확정 전 하드코딩하지 않는다.
- [ ] 구현 보고와 현재 체크아웃 증거를 구분한다.
- [ ] G0 미완성 계약·픽스처를 완료로 표시하지 않는다.
- [ ] 고립은 범위·데이터 단절보다 먼저 평가한다.
- [ ] 공식 대피 지시와 도로 통제를 같은 행동 조건으로 묶지 않는다.
- [ ] `EVACUATE` 경로 실패를 안전정책 합의 전 `EMERGENCY`로 자동 전환하지 않는다.
